# 本地开发

当前运行模式是 **真实模型 only**：没有完整的 `MODEL_*` 配置时，API 和 Worker 会在启动时失败；模型请求失败、超时或结构化输出不合法时，任务会显式失败，不生成替代数据。

## 环境

- Node.js >= 22.13
- pnpm 11+
- Docker Desktop
- 一个 OpenAI 兼容的模型接口（支持 `POST /chat/completions` 与 `response_format: { type: "json_object" }`）

## 第一次配置

```bash
cd mastra-short-drama-agent
pnpm install
cp config/.local.env.example config/.local.env
```

编辑 `config/.local.env`，至少填写：

```env
MODEL_BASE_URL=https://api.openai.com/v1
MODEL_API_KEY=...
MODEL_NAME=...
```

三个环境模板均已提供，真实值不提交：

- `config/.local.env.example`：本地开发，PostgreSQL `short_drama`，Redis `localhost:6380`
- `config/.test.env.example`：测试环境模板，Redis 使用 DB 1、API 端口 4121
- `config/.production.env.example`：生产部署模板

## 启动本地依赖

```bash
pnpm infra:up
pnpm db:deploy
```

这会启动：

- PostgreSQL 16：`localhost:5434`
- Redis 7：`localhost:6380`

检查依赖：

```bash
docker compose ps
```

停止依赖但保留数据：

```bash
pnpm infra:down
```

清空本地数据库（破坏性操作）：

```bash
pnpm db:reset-local
pnpm db:deploy
```

不要用 `docker compose down -v`，除非你确认要删除 PostgreSQL 和 Redis 数据卷。

## 启动开发服务

分别打开三个终端：

```bash
# 终端 1：Nest API，默认 http://localhost:4120
pnpm dev:server
```

```bash
# 终端 2：任务 Worker
pnpm dev:worker
```

```bash
# 终端 3：React/Vite，默认 http://localhost:5173
pnpm dev:web
```

打开 `http://localhost:5173`，登录：

```text
用户名：demo
密码：demo123
```

健康检查：

```bash
curl http://localhost:4120/api/health
```

预期同时显示：

```json
{"ok":true,"service":"short-drama-api","database":"ok","redis":"ok"}
```

## 最小真实模型冒烟测试

配置 `config/.test.env` 后执行：

```bash
APP_ENV=test pnpm --filter server test:real
```

脚本会用 1 集、4 镜调用真实模型，依次验证：

```text
StoryBible → Scene → 4 × Shot → Reviewer
```

输出应包含真实模型名、每个镜头的 attempts 和 Reviewer 结果。

## 完整手工验收

1. 浏览器登录并新建项目；
2. 粘贴剧本；
3. 输入集数 `1`；
4. 输入镜头数 `8`；
5. 在 Worker 终端确认每个模型阶段都有请求日志；
6. 在页面确认资产、场次、分镜和 Prompt 来自本次剧本，而不是固定模板；
7. 输入“把林小雨的风衣改成深灰大衣”，确认影响范围并局部重生成；
8. 测试措辞问题自动修订、事实问题忽略、单镜重试；
9. 点击“导出项目 ZIP”，检查 `manifest.json`；
10. `docker compose restart` 或重启 Worker，确认任务和数据仍在。

## 真实模型失败调试

Provider 对每个请求最多尝试 3 次，指数退避。失败时输出结构化日志：

```json
{"event":"model_request_failed","agent":"...","model":"...","attempt":1,"error":"..."}
```

排查顺序：

1. `MODEL_BASE_URL` 是否包含正确的 `/v1`；
2. `MODEL_API_KEY` 是否有效；
3. `MODEL_NAME` 是否存在；
4. 服务是否支持 JSON response format；
5. 返回 JSON 是否满足对应 Zod Schema；
6. 查看 API/Worker 终端的错误日志和数据库 `DomainTask.error`。

模型失败不会生成替代结果，也不会写入伪造的资产。


```bash

```

## 生产模板

生产环境不要使用本地 compose 的端口和默认密钥。复制：

```bash
cp config/.production.env.example config/.production.env
```

通过部署平台的 Secret 管理器填写数据库、Redis、模型 Key、`SESSION_SECRET` 和 `ADMIN_TOKEN`。`config/.production.env` 已被 gitignore 忽略。
