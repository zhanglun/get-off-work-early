# 短剧制作协作 Agent：产品简报

> 状态：v0.1 设计基线
> 最后更新：2026-08-29（产品决策已确认）

## 1. 产品定位

本项目不是单纯的分镜提示词生成器，也不是泛化的编剧聊天机器人，而是一个：

> 面向短剧内容制作团队的 AI 制作协作系统。

它帮助团队把一集短剧剧本转化为可理解、可审查、可修改、可导出的生产资产。

核心目标：

```text
剧本
  → 故事世界模型
  → 场次与分镜
  → 画面/视频提示词
  → 一致性审查
  → 修改与确认
  → 生产资料包
```

## 2. 目标用户

第一阶段主要服务：

- 编剧助理
- 导演/分镜师
- AI 内容生产人员
- 短剧项目负责人

优先用户画像：

> 已经拥有剧本，需要快速整理成角色、场景、场次、分镜和生成提示词，并希望能够审查和反复修改的内容制作人员。

本项目第一阶段不优先服务普通观众，也不以自动写完整剧本为主要目标。

## 3. 产品形态

采用：

```text
聊天入口 + 结构化资产工作区
```

聊天负责：

- 表达创作意图
- 发起分析或生成任务
- 请求局部修改
- 询问某个资产的依据
- 查看任务进度和审查结果

结构化工作区负责：

- 展示剧本、角色、场景、道具、场次和分镜
- 编辑资产
- 查看版本差异
- 审查 Agent 提议
- 确认关键变更
- 导出生产资料

聊天不是业务事实来源。结构化业务资产是 Source of Truth。

## 4. 第一阶段目标

第一阶段采用“项目壳 + 一集闭环”：

```text
Project
  └── Episode 01
       ├── ScriptVersion
       ├── StoryBible
       ├── Scenes
       ├── Shots
       └── ExportPackage
```

输入：

- 一集约定式 Markdown 剧本
- 兼容基础场次格式和接近行业剧本的格式
- 可选的用户补充说明

输出：

1. 剧本摘要
2. 角色卡
3. 场景卡
4. 道具清单
5. 剧情事件和时间线
6. 场次列表
7. 分镜列表
8. 画面提示词
9. 视频提示词
10. 一致性审查报告
11. 修改记录和版本差异
12. Markdown / JSON 生产包

## 5. 已确认的第一版产品决策

| 决策项 | 结论 |
|---|---|
| 目标用户 | 短剧内容制作团队 |
| 产品范围 | Project 外壳 + 单项目单集实跑 |
| 主要交互 | Chat-first，同时提供结构化资产工作区 |
| 事实来源 | 结构化业务资产 |
| StoryBible | 生成后必须确认才能继续生产 |
| 确认入口 | 工作区按钮和聊天都调用同一个 Confirm API |
| 冲突策略 | 高风险冲突阻断确认，低置信度信息可标记继续 |
| 聊天形态 | 命令路由 + 创作问答，暂不做开放式总控 Agent |
| 剧本输入 | 约定式 Markdown，兼容基础和接近行业格式 |
| API 执行 | 异步 Workflow；Studio 用于调试 |

## 6. 核心用户旅程

```text
创建项目
  → 创建第一集
  → 导入剧本
  → Agent 解析剧本
  → 用户必须确认故事资产
  → Agent 生成场次和分镜
  → 用户确认或局部修改
  → Agent 生成画面/视频提示词
  → 自动一致性审查
  → 普通问题自动修订
  → 关键变更请求确认
  → 用户确认导出
```

## 7. 聊天能力边界

第一阶段聊天 Agent 同时支持两类意图：

### 生产指令

- 分析这一集剧本
- 生成或重新生成故事资产
- 生成场次和分镜
- 重新生成指定镜头
- 解释审查问题
- 展示版本差异
- 导出当前确认版本

### 创作问答

- 解释人物动机和关系
- 讨论剧情结构、冲突和悬念
- 询问角色、场景、道具和时间线
- 对对白、情绪和节奏提出建议

创作问答默认是建议，不直接改变结构化资产；如果用户要求落地修改，必须转换为明确的变更提议或 Workflow 操作。

聊天 Agent 不直接伪造生产结果，也不绕过确认门槛。

## 8. Agent 的边界

Agent 可以：

- 理解剧本和隐含关系
- 提取角色、场景、道具和事件
- 提出结构化内容
- 生成分镜和提示词
- 发现连续性问题
- 生成修改提议
- 解释生成依据

Agent 不应直接绕过业务层修改全局事实。Agent 产生的是：

```text
结构化结果 / 修改提议 / 审查报告
```

由 Workflow、领域规则和用户确认决定是否提交。

## 9. 关键产品原则

### 7.1 结构化资产优先

任何可复用、可编辑、可审计的信息都应进入结构化资产，而不是只停留在聊天文本中。

### 7.2 事实和推断分离

角色外观、场景布局、道具状态等信息需要标记来源：

```text
script / user / agent / derived / imported-legacy
```

### 7.3 局部重跑优先

用户修改一个角色或一个场次时，不应默认重新生成整集。系统应该能够按影响范围局部重跑。

### 7.4 关键变更可审查

涉及角色锚点、场景固定布局、时间线和跨镜头规则的变更，需要展示 before/after、影响范围和变更原因。

### 7.5 旧系统不是核心依赖

旧系统对接和新旧盲测属于可选的对比能力。没有旧系统时，主流程仍然必须可以独立运行。

## 10. 第一阶段成功标准

不是“模型返回了一段文字”，而是：

- 一集剧本可以稳定解析为结构化资产
- 角色、场景和道具可以被后续步骤复用
- 可以生成有镜头语言的分镜
- 可以生成画面和视频提示词
- 审查能发现至少一类真实连续性问题
- 普通问题可以自动修订
- 关键变更会请求用户确认
- 每次修改都可追溯和回退
- 结果可以导出为 Markdown 和 JSON
- 失败的单个步骤不会导致整个项目数据不可用
