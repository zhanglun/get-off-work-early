## 2. 待确认缺口与推荐方案

### G1：低风险自动修订的边界（§5.4）

PRD 规定"支持自动修订低风险问题"，但未定义什么算低风险。

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | **只动措辞不动事实**：自动修订仅限措辞、格式和明确性改进；涉及角色、道具、事件等事实内容的问题只标记不修改 | 事实层问题需人工处理 |
| B | 模型置信度阈值决定（如 ≥0.9 自动修订） | 有事实漂移风险，阈值难标定 |
| C | 第一版不做自动修订，全部人工 | 问题多时体验差，§5.4 条款需删除 |

推荐理由：A 与"用户始终可以看到和修改结构化资产"的可控性原则一致；修订是否越界可以用规则判定（是否触及事实字段），可解释、可测试。

### G2：影响范围重生成的执行方式（§5.2）

编辑故事资产后"自动重新生成受影响内容"——改一个主角设定可能波及几十个镜头。

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | **全自动后台执行**：保存即计算影响范围并后台重生成，进度实时可见，可随时取消；不阻塞继续编辑其他卡片 | 触发大范围重生成时消耗时长/成本 |
| B | 自动算范围，展示受影响清单，用户确认后执行 | 引入确认步骤，与"不做正式审批"决策略有张力 |
| C | 规模分档：≤5 个镜头自动，超过需确认 | 多一条规则要维护和测试 |

推荐理由：A 是 CONTEXT.md 已确认的"自动识别影响范围，自动重生成"的直接落实；体验连续，且"进度可见 + 可取消"已经覆盖了成本失控的兜底。

### G3：生成时长目标（§4.2）

成功标准没有任何时间预算。

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | **Mock 定硬指标**：Mock 模式全链路（导入→资产→场次→分镜→问题→可导出）≤ 2 分钟，列入验收；Real 模式第一版不设硬指标，只要求进度实时可见、失败可重试 | Mock 指标需在实现后校准 |
| B | 不设任何时长指标 | "能跑但慢到不可用"无法在验收时暴露 |
| C | Mock 和 Real 都定硬指标 | Real 依赖外部模型服务，波动大，易误伤验收 |

推荐理由：Mock 链路可控可复现，适合作为工程验收闸门；Real 的波动性不适合第一版定死指标。

### G4：导出清单是否锁定（§5.6）

9 文件清单（5 Markdown + 4 JSON）是否为第一版标准。

| 选项 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | **锁定 9 文件清单**，CSV/Excel 留二期，保持第一版范围封闭 | 外部协作者需自行处理 JSON |
| B | 增加分镜表导出（CSV/XLSX） | 多一项实现与测试；§7"不做表格"指主界面，不冲突但扩大范围 |

推荐理由：第一版原则是范围封闭；生产包面向"后续制作人员使用"，Markdown + JSON 已满足，表格导出等真实需求出现后再加。
