# 信息架构 v2：对话形态

> 状态：2026-08-30 随产品形态决策（`product-form.md`）重写，待评审
>
> 目标：用户以"对话 + 工件"理解系统，而不是页面和导航。让用户以"项目、剧集、资产、问题、导出"的方式理解内容本身。

## 1. 界面分区

```text
┌──────────┬──────────────────────────────┐
│ 会话历史栏 │        对话主区               │
│ （导航即  │  用户消息 · 活动流 · 工件      │
│  历史）   │  ……                          │
│          │  [ 输入框（常驻底部） ]        │
└──────────┴──────────────────────────────┘
```

没有页签、没有面包屑、没有仪表盘。会话历史栏承担原导航职责：每个项目 × 集 = 一个会话，点击即切换。

## 2. 会话历史栏

| 元素 | 说明 |
|---|---|
| 新会话按钮 | 回到空态第一屏 |
| 会话列表 | 项目名 · 集数 + 状态标（生成中 x% / 已完成 / N 个待处理问题） |
| 会话项状态 | 从任务状态实时同步；点击进行中的会话回到活动流 |

## 3. 空态（第一屏）

居中：品牌 + 邀请语（"把一集剧本贴进来"）+ 输入框。

输入框能力：

- 粘贴文本；
- 拖入 / 选择 `.md` `.txt` 文件；
- 发送前需补齐：项目名称、第几集（缺失时输入框上方就地提示，不跳页）。

第一屏必须交代（与 PRD §2 一致）：

- 自动生成包含哪些内容；
- 生成中可以离开，回来接着看；
- 发现问题不会中断整集任务。

## 4. 对话主区

从上到下依次为：用户消息 → 活动流 → 工件 → …… → 输入框（常驻底部）。

### 4.1 用户消息（剧本）

- 默认折叠，显示"剧本 · 8,412 字 · 第 3 集"；
- 展开可查看原文（对应原"原始剧本页"职责）。

### 4.2 活动流

- 阶段行：`✓ 剧本解析 · 3.2s`、`● 分镜生成 26/42`、`○ 连续性检查`；
- 运行中：当前阶段展开、含细进度；已完成阶段折叠；
- 完成后：整块折叠为一行"生成完成 · 用时 00:01:48 · 展开"；
- 失败项以问题工件呈现，不在活动流里堆原始错误。

### 4.3 工件

渲染规范见 `product-form.md` §3。界面规则：

- 工件随生成实时出现，不滚出屏幕外（新工件追加时对话自动跟随底部；用户上滑阅读时不强制拉回）；
- 展开状态跟随用户操作，不被后续事件重置；
- 每个工件有稳定身份（activityId），重试/重生成后原位更新并标注新版本，不重复堆叠。

### 4.4 输入框

- 常驻底部；对话与指令同一入口；
- 支持 `/` 快捷指令（导出、只看第 N 场、重试镜 N）与自然语言并行；
- 运行中输入框可用：允许边生成边补充要求，agent 排队处理。

## 5. 状态与恢复

- 刷新 / 换设备：按会话 ID 从服务端恢复全部消息、工件与折叠状态；
- 生成中离开再回来：活动流续播当前进度，不重复执行；
- 会话终态后仍可继续对话（修改、重试、导出）。

## 6. 术语规范

不变（沿用 v1）：面向用户用"故事资产、角色卡、场次、分镜、问题、重试、版本、生产包"；面向开发用 StoryBible / Scene / Shot / PromptVersion / Review / DomainTask。界面不出现后者。

## 7. 响应式

- 第一版优先桌面端（≥1100px 显示历史栏）；
- 窄屏：历史栏收起为抽屉，对话主区全宽；
- 工件卡片单列堆叠，输入框吸底。
