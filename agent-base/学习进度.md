## v1 主链路（最终版）

```
POST /tasks(剧本+配置) → 任务中心建档 → BullMQ 入队
→ LegacyImporter 调旧接口拿分镜列表+旧提示词（落 OldShot=盲测基线）
→ 每镜 Shot Loop（Director→Reviewer→Refiner，通过即停≤3轮熔断）
→ 落库 + 进度回写任务中心
→ 盲测打分页：GET pairs（随机侧序随任务缓存）→ 逐镜选优+双分 → POST scores（归因落 Score 表）
```

## 已锁定决策（grilling 三会话累计）

**范围与靶心**：周五客户内测盲测打分、对比赢=成功；镜头级打分（不做整集分，专注单镜优化）；用户只定架子，4 人按模块分工；周五必须真跑（mock 不能上 demo）。

**架构**：沿用旧系统切分（旧接口导入分镜+旧提示词，Parser 降为 demo 后）；异步任务式（BullMQ worker，一集一 job，镜级并发 P=4 可配）；任务数据/状态由公司任务中心维护（适配层+mock 降级）；每镜独立 generator-critic loop（≤3 轮熔断可配，通过即停）；防穿帮=输入侧上下文注入+Reviewer 规则双管。

**技术栈**：NestJS + Prisma/PostgreSQL + BullMQ/Redis + zod + OpenAI 兼容 LLM 封装（复用原团队端点）。**不用 LangGraph**（loop 是直线循环，手写 20 行；框架负资产——决策论证已沉淀在 team-review.md FAQ）。

**盲测设计**：服务端随机侧序+随任务缓存（防顺序偏好、防记位置）；打分=逐镜选优+1-5 双分；sideOrder 归因落库可审计；砍实时看板（后台查库/导出报表）；内测小规模、token 成本不监控。

**知识源**：原团队 prompt 起点 + LLM 生成规则草稿 + 人工筛选。
