## 1. 一页纸：这是什么、为什么、怎么赢

**做什么**：替代原团队的「剧本→分镜提示词」系统。原系统 = 单次 LLM 调用直出，客户反馈提示词不好（镜头穿帮类）。

**我们做什么不同**：每镜提示词走 **生成→审查→改写** 的自动优化循环（generator-critic），全程留痕，输出带推理（rationale）和审查记录（review_log）。

**怎么证明更好（周五验收）**：客户自助盲测——逐镜新旧提示词并排（随机侧序、不知哪边是新的），选优+打分（1-5 双分）。用数据说话。

**关键技术决策一览**（详见 architecture.md）：

| 决策 | 选择 | 一句话理由 |
|---|---|---|
| 分镜来源 | **沿用旧系统切分**（接口导入） | 盲测要求新旧同镜对齐；专注单镜优化；去掉最不可控环节 |
| 架构形态 | 异步任务式（BullMQ worker） | 一集几十镜×多轮 = 分钟级，HTTP 里跑不动 |
| 优化循环 | 每镜独立 loop，审查通过即停，3 轮熔断 | 成本可控、故障隔离；轮数可配 |
| 防穿帮 | 输入侧注入角色卡+相邻镜上下文 + Reviewer 规则拦截双管 | 穿帮=镜内逻辑+镜间一致性两类 |
| 技术栈 | NestJS + Prisma/PG + BullMQ/Redis | 团队既有基建；社区成熟案例 |
| 任务状态 | 公司任务中心（适配层+mock 降级） | 复用既有模块，不重复造 |
| LLM | OpenAI 兼容封装，复用原团队端点，可切换 | 调试期灵活换模型 |
| 盲测 | 服务端随机侧序+随任务缓存 | 防顺序偏好污染数据 |
| **不用 LangGraph** | 手写 while 循环 | loop 是简单直线循环，框架是负资产；详细论证见 §7 |

## 2. 主链路（30 秒版）

```
POST /tasks(剧本+配置) → 任务中心建档 → BullMQ 入队
→ LegacyImporter 调旧接口拿分镜列表+旧提示词（落 OldShot=盲测基线）
→ 每镜 Shot Loop: Director 生成优化版 → Reviewer 按规则审查 → 不过则 Refiner 改写
   （通过即停，≤3轮，仍不过标记 needs_review 保留最后版）
→ 落库 + 进度回写任务中心
→ 盲测打分页: GET pairs（随机侧序）→ 客户逐镜选优+双分 → POST scores（归因落 Score 表）
```

## 7. FAQ（review 时可能问到的）

**Q：不用 LangGraph，这算 agent 吗？**
A：这是「固定工作流 + LLM 节点 + 自我修正循环」——严格叫 agentic workflow。自主决策点（动态轮数、LLM 自选动作、挂工具）是 demo 后演进方向；框架不是智能的来源，Claude Code/Manus 都是手写 loop。周五目标是「盲测分数赢」，与框架无关。

**Q：为什么上限 3 轮？**
A：通过即停（预计多数 1-2 轮过），3 是防失控熔断，config 可配。跑真实数据后按「通过轮数分布」调整；大量卡 3 轮说明 prompt 问题（加轮数不解决）。

**Q：打分页能保证公平吗？**
A：盲测（客户不知哪边是新的）+ 随机侧序随任务缓存（同一任务所有人看到相同随机顺序，防顺序偏好+防记位置）。分数按 sideOrder 归因落库，事后可审计。

**Q：任务中心挂了怎么办？**
A：适配层含 mock 实现（env 切换），全链路不依赖任务中心可用性；真实接口到了只改 task-center/ 模块。
