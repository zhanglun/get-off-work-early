## 1. 项目背景

- 现有系统（其他团队实现）：前端调接口，接口内部将剧集内容单次调用大模型，直接返回分镜提示词；另有单次调用的「优化提示词」功能
- 问题：客户反馈提示词不好，存在镜头穿帮类问题
- 老板决策：重做一个新系统替代原团队能力，方向是 agent 智能化（自动审查、自动优化等能力）
- **2026-08-16 决策更新**：先按 workflow 实现业务需求（盲测赢为靶心），agent 化作为演进方向不预建——见 [workflow-vs-agent.md](./workflow-vs-agent.md)

## 2. 最终目标

1. **近期（本周五）**：发布测试版 + 前端验证页面（新旧输出对比 + review_log 可视化）
2. **中期**：替代原系统，向前端提供新接口
3. **远期（方向性）**：成长为短剧场景的通用能力平台，持续增加能力（本期不预建）

## 3. 用户与使用方式

| 角色 | 说明 |
|---|---|
| 前端调用方 | 内部系统，通过 API 提交剧本、轮询任务、获取分镜表 |
| 客户（原有客户） | 消费最终提示词，全自动直达，无人工审核环节 |
| 客户（内测打分者） | 自助访问盲测打分页：逐镜新旧并排（随机侧序）、选优+打分（1-5 双分） |
| 开发团队 | 周二起 4 人并行：盲测打分页 / prompt 调优+穿帮规则 / 模板配置+部署联调 / 测试+数据+报表 |

## 4. 功能需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 剧本提交 | 输入剧集文字内容，在**任务中心**创建异步任务并返回任务 ID，入队处理 |
| F2 | 任务查询 | 按任务 ID 查询状态、进度、结果——**状态与任务数据由任务中心维护**，本服务透传/聚合 |
| F3 | 分镜来源（v1 变更） | **沿用旧系统切分**：调旧接口拿分镜列表+旧提示词（结构化 JSON）作输入与盲测基线；自切分 Parser 降为 demo 后功能 |
| F4 | 镜头生成 | 每镜输出：镜头决策 + 推理（rationale）+ 优化后提示词（旧提示词为起点，不是从零生成） |
| F5 | 自动审查 | 审查规则：镜头语言 + 画面逻辑（穿帮）+ 相邻镜一致性 |
| F6 | 自动优化 | 审查不过自动改写，≤3 轮（可配），超限标记 needs_review |
| F7 | 全程留痕 | 每镜每轮的审查发现、修改记录、迭代次数可查（review_log） |
| F8 | 新旧对比（v1.1 变更） | **盲测 A/B**：验证页逐镜新旧并排（服务端随机侧序落库+顺序稳定），客户逐镜选优+双分（1-5）；winner 支持 tie（平局进分母不进分子）；服务端按落库侧序自查归因（客户端不可传侧序）；同人同镜一票（重复提交 409）；分数据落库可审计 |
| F9 | 模板配置位 | 下游视频模型由客户选择——提供提示词模板配置，不接生成 |
| F10 | 内测报表 | 打分数据落库，内测期间后台直查库/导出出报表（平均分、新旧胜率、逐镜明细）——不做实时看板 |

## 5. 非功能需求

| # | 需求 | 说明 |
|---|---|---|
| N1 | mock 可跑通 | LLM 端点未定时，全链路用 mock LLM 跑通（真实端点换 env 即可） |
| N2 | 成本计量 | 逐镜统计 token，任务级汇总，验证页可见 |
| N3 | 故障隔离 | 单镜失败不影响同集其他镜 |
| N4 | 时效 | 一集分钟级完成（异步任务式，非实时） |
| N5 | 任务中心依赖 | 异步任务的数据与状态由公司任务中心模块维护；本服务通过适配层对接，**任务中心不可用时全链路仍可用 mock 跑通**（同 N1 策略） |

## 6. 范围边界（本期不做）

- 下游视频生成的实际对接（只提供模板配置位）
- 跨集长期记忆/角色库（Context Builder 留扩展点）
- 人工审核工作流（全自动，review_log 供事后核查）
- 多租户/权限/插件系统

## 7. 假设（非用户确认，样例到手后修正）

- 单集剧本 3k-1 万字、几十个分镜
- 旧系统接口返回结构化 JSON 含分镜列表+提示词（周一拿接口文档验证）
- LLM 端点周一可拿到（已确认）；真实剧本周一去拿（优先客户反馈过差的段落）
- 任务中心接口形态假设：负责任务建档/状态流转/进度记录，**不负责执行调度**（执行仍走 BullMQ）；若它还能调度执行，BullMQ 可去掉——待拿到任务中心接口文档后确认
