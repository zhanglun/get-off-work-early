# 转型路线图：Web 全栈 → 机器人 / 具身智能软件平台

> 配套阅读：《求职公司筛选手册.md》——转型期间面试，筛公司标准不变
> 核心认知：**你不是转行，是迁移。** 11 年工程 + 平台 + AI 应用层能力直接带走，领域只是新的上下文。


---

## 一、转型定位（先想清楚，再动）

**你要做的岗位**：机器人 / 具身智能公司的**平台 / 工具链 / 数据平台工程师**

- 数据采集、清洗、标注平台
- 训练任务调度、模型管理（你九州干的活的机器人版）
- 仿真可视化、遥操作 UI、管理后台
- MLOps / 数据闭环基础设施

**你不做的**（转型陷阱，别碰）：
- ❌ 算法 / 模型训练本身（那是算法工程师）
- ❌ 控制 / 嵌入式 / C++ 底层（那是控制工程师）
- ❌ 从头学分子生物学去做研究（生物方向只做平台，不做研究）

**为什么这个定位成立**：机器人公司普遍算法强、工程烂，**极度缺能把领域需求翻译成软件的工程师**——你 11 年软件工程 + AI 平台经验，在这个位置上是稀缺品。

**方向排序**：机器人 / 具身智能 > 生物+AI（杭州产业、经验迁移距离、已有试探，三者都指向机器人）。

## 二、领域概念地图（2-4 周，能对话就行）

**目标：能听懂领域工程师说话，不是变成他们。**

### 机器人软件栈分层

```
┌─────────────────────────────┐
│  上层：云平台 / 数据 / 管理    │ ← 你的主场（Web 全栈）
│  数据平台、训练平台、可视化     │
├─────────────────────────────┤
│  中层：感知 / 规划 / 控制      │ ← 领域工程师的地盘，你只需听懂
│  SLAM、路径规划、决策          │
├─────────────────────────────┤
│  底层：嵌入式 / 电机 / 执行器   │ ← 你不碰
└─────────────────────────────┘
```

### 具身智能数据闭环（你的业务地图）

```
数据采集(真机/仿真) → 清洗/标注 → 训练 → 仿真验证 → 部署 → 数据回传 → 再采集
      ↑_________________________ 闭环 _________________________↓
```

**你在闭环里的位置是"承载数据的软件"**——采集端工具、标注平台、数据版本管理、训练任务调度、可视化。闭环的每个环节都需要软件，这就是你的工作范围。

### 必须认识的概念（每个查 30 分钟，能解释即可）

| 概念 | 是什么（一句话） | 为什么你要知道 |
|---|---|---|
| ROS / ROS2 | 机器人软件框架，节点间通信 | 领域工程师天天用它，你要能接话 |
| 仿真（Isaac Sim / Gazebo / MuJoCo） | 虚拟环境里训练和验证机器人 | 数据的重要来源，训练平台要对接它 |
| 遥操作（teleop） | 人远程操控机器人，采集数据 | 数据采集环节，你的工具链要支撑 |
| 数据闭环 / data flywheel | 数据→训练→部署→新数据 的正循环 | 就是你的业务地图 |
| ROS bag | 传感器数据打包格式 | 数据的"文件格式"，你的平台要处理它 |
| 传感器类型 | 相机、激光雷达、IMU、关节编码器 | 你要设计的数据，就是这些来源 |
| 具身智能数据集 | Open X-Embodiment 等开放数据集 | 了解数据长什么样、怎么组织的 |
| MLOps 工具 | MLflow / Kubeflow / DVC / Label Studio | 训练生命周期、数据版本、标注——你的核心工具集 |
| fleet 管理 | 多台机器人统一管理 | 云端平台的高层能力 |

### 学习资源（具体看什么）

- **ROS 2**：官方文档 docs.ros.org 的 Tutorials 前几节，知道节点/话题/消息即可，不写代码
- **仿真**：NVIDIA Isaac Sim 官方入门文档，跑一个 Hello World
- **具身智能全局认知**：搜"具身智能 综述"（中文即可，知乎/B站都有好系列），把数据闭环讲清楚的那种
- **数据平台工具**：DVC（数据版本控制）、Label Studio（标注）各花半天玩一遍——**这两个是你能马上上手、也最可能写进简历的**
- **真实数据长什么样**：下载 Open X-Embodiment 或一个 ROS bag 看看里面是什么

## 三、技术补强（4-8 周）

| 补什么 | 为什么 | 怎么补 |
|---|---|---|
| **Python 数据科学级**：numpy / pandas / 数据处理 | 平台岗绕不开数据处理 | 不买课，直接拿一份传感器数据练手清洗、聚合、可视化 |
| **把已有 AI 平台经验翻译成机器人语境** | 你九州做过任务中心、模型统一接入、AI 长任务调度——**这些需求在机器人训练平台一模一样，只是数据从视频变成传感器轨迹** | 写一份"我在九州做的事 → 机器人训练平台对应什么"的映射表（简历会用到） |
| **MLflow 是什么、解决什么问题** | 面试纽鼐这类公司的基础词汇 | 官方文档 1 小时 + 本地跑通一个 demo |
| **K8s 基础概念**（可选但建议） | 平台岗 JD 高频出现 | 不深学，知道 pod/deployment/调度概念即可 |

**不学**：C++ 底层、电机控制、ROS 深度编程、深度学习炼丹——都不是你的岗位范围。

## 四、作品策略（最重要的护城河，6-12 周）

**没有作品：简历 = "11 年 Web 想转行"（被筛）**
**有作品：简历 = "能把领域需求翻译成软件的平台工程师"（被抢）**

### 方案 A（首选）：具身智能数据管理平台 demo

用你 11 年的全栈能力，做一个你九州工作的"机器人版"：
- 数据集上传 / 列表 / 版本管理（模拟传感器数据）
- 标注任务分配、进度可视化
- 训练任务提交、状态跟踪（复用你九州任务中心的经验）
- 前端 React + 后端 Node/FastAPI，数据可视化

**技术栈全是你的，只换数据对象**——这就是"迁移"最直观的展示。

### 方案 B：参与开源

- **Foxglove**（机器人数据可视化 Web 工具，活跃）——修 issue、提 PR
- ROS 生态的 Web 工具
- 具身智能开源项目的数据平台部分

### 方案 C：真实痛点小工具

找个机器人公司的实际痛点做个工具（如：遥操作延迟可视化、数据集质量检查脚本）。

**作品三要点**：能跑、有 README 说明解决了什么、能讲清楚领域背景（面试时讲"我发现领域工程师有 XX 痛点，做了 XX 解决"——这就是"翻译能力"的证据）。

## 七、怎么思考（贯穿全程）

1. **倒推法代替发散法**：别问"我该学什么"——去机器人公司招聘页看 10 个平台岗 JD，把重复技能抄下来。**JD 就是你的课程表**（纽鼐那份是第一课）
2. **保持筛选思维**：学习也筛——不学嵌入式是定位问题不是能力问题。面试继续用筛选手册，别因为"转型期"降低标准
3. **别停**：转型期最大的敌人是自我怀疑。**每天推进 30 分钟，比每天焦虑 8 小时强**
4. **你的账已经算清了**：6 个月的转型投入，换一个热爱的领域——你连九州的账都能算清，这笔账不难
